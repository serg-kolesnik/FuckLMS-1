# AGENTS.md

Инструкции для OpenCode-сессий в этом репозитории. Цель — не наступить на грабли, которые не видны по именам файлов.

## Обязательный порядок работы при любом запросе, меняющем код

Выполнять по шагам, не пропуская:

1. **Документация.** Прочитать всё в `docs/`: `README.md`, `network-api.md`, `openapi.yaml`, `app-flow.html` и все файлы в `docs/adr/`. Документация — источник правды по контракту с Moodle; код менять только после сверки с ней.
2. **ADR — если меняется архитектурный подход.** Новое решение (новый механизм работы с LMS, смена хранения данных, новая библиотека/паттерн) → **до написания кода** создать `docs/adr/NNN-короткое-имя.md` (нумерация с `0001`, имя латиницей) с разделами: `Статус`, `Контекст`, `Решение`, `Последствия`. Мелкие правки и багфиксы ADR не требуют.
3. **Код.** Минимальные изменения под задачу. Не трогать то, что не относится к запросу.
4. **Чек-ревью.** Самопроверка diff'а: сборка `./gradlew assembleDebug` проходит; изменения не ломают описанный в docs контракт — если ломают, синхронно обновить `network-api.md` / `openapi.yaml` / `app-flow.html`; нет отладочного мусора (Log.d, закомментированного кода).
5. **Коммит.** Одна логическая правка = один коммит, только файлы своей задачи. Стиль сообщений по истории репо: английский, повелительное наклонение (`Add ...`, `Fix ...`, `Update ...`).

## Правила ограничений

- **Только файлы внутри репозитория.** Ничего не изменять за пределами корня проекта (нет записей в `~/.gradle`, Android SDK, системные конфиги, другие проекты).
- **Новый стек — только после согласования.** Новые зависимости, Gradle-плагины, build-фичи, замена библиотек — сначала спросить разработчика и дождаться явного одобрения. Это касается и `gradle/libs.versions.toml`, и хардкода версий в `app/build.gradle.kts`.

## Архитектура — неочевидные факты

- Два компонента: Android-приложение (`:app`) и **Go-сервис** (`server/`, PostgreSQL —
  таблица `students`). Приложение общается **только с сервисом** (JSON + SSE,
  bearer-токен); всю работу с Moodle LMS (`https://lms.uni-dubna.ru`, захардкожен в
  `server/lms.go` и `server/config.go`) делает сервис. Контракт API — `docs/openapi.yaml`,
  решение — `docs/adr/0001-go-attendance-service.md`.
- Входная точка — `MainActivity.kt`, три Compose-экрана: `ScannerScreen` (CameraX + ML Kit,
  без изменений), `MarkingScreen` (POST `/api/mark` + чтение SSE-потока через OkHttp),
  `AccountsScreen` (CRUD студентов через API + карточка настроек сервиса).
- `ServiceClient.kt` — весь сетевой слой приложения: `ServiceSettings` (адрес + токен в
  `EncryptedSharedPreferences`, файл `secure_service_prefs`) и `ServiceClient` (OkHttp,
  ручной разбор SSE-строк `event:`/`data:`). Пароли студентов в приложении не хранятся
  и не отображаются.
- Удалено в рамках ADR 0001: WebView-ветка `BrowserScreen` с JS-инъекциями,
  `MoodleClient.kt`, `AccountManager` и файл `secure_accounts_prefs` — **не
  восстанавливать без нового ADR**. Старые сохранённые на устройствах аккаунты
  не мигрируют (по решению — заново вносятся в БД сервиса).
- `QrParser.parseQrUrl()` по-прежнему **не подключён к UI**: сканер передаёт сырую
  QR-ссылку целиком, `sessid`/`qrpass` разбирает сервис (`server/mark.go`,
  приоритет `qrpass` → `password` → `studentpassword`).
- Манифест включает `android:usesCleartextTraffic="true"` — сервис в LAN обычно по http.
- Механика Moodle на сервисе: логин через скрытое поле `logintoken`, отметка через
  `sesskey` + выбор радиокнопки статуса **по подписи** (хардкод `status=1` запрещён);
  «уже была отмечена» → статус `already` (успех). Константа
  `view.php?id=122864&success=true` больше нигде не используется.
- `minSdk = 24` в `:app` — используемые API должны существовать с Android 7.0.

## Сборка и проверка

```bash
./gradlew assembleDebug          # основная проверка; APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:compileDebugKotlin  # быстрый чек компиляции без упаковки
cd server && go build ./... && go vet ./...  # проверка Go-сервиса
```

- Нужен **JDK 17+** (AGP 9.x); Android SDK через `local.properties` или `ANDROID_HOME`.
- Реальных тестов **нет** — только шаблоны `ExampleUnitTest`/`ExampleInstrumentedTest`. Не предлагать `./gradlew test` как проверку и не выдумывать тест-команды; верификация = сборка + ревью.
- CI, линтеров и форматтеров нет. Конфиг-кэш Gradle включён (`org.gradle.configuration-cache=true`).
- Release: R8-оптимизация отключена (`optimization { enable = false }`), подписи нет — `assembleRelease` даёт неподписанный APK. Keep-правила R8: `app/src/main/keepRules/rules.keep`.
- Версии: androidx/compose — централизованно в `gradle/libs.versions.toml`; camerax, mlkit, okhttp, security-crypto, icons — хардкодом в `app/build.gradle.kts`.

## Соглашения

- Комментарии и UI-строки — **русские**; `docs/` — русские; `docs/openapi.yaml` — английский. Идентификаторы кода — английские.
- `docs/` поддерживается вручную и должен соответствовать коду: любое изменение потока отметки/логина/хранения → обновить соответствующие доки в том же коммите.
