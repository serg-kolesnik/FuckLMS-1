# Документация FuckLMS

Здесь собраны материалы о том, как устроена и работает система.

> ⚠️ Репозиторий находится в переходном состоянии (см. [ADR 0001](adr/0001-go-attendance-service.md)):
> документация описывает **целевую архитектуру** — приложение-клиент + Go-сервис + PostgreSQL.
> Реализация сервиса идёт в ветке `service/refactor`; до её слияния код в `master` ещё работает
> по прежней схеме (WebView-автоматизация).

| Файл | Что содержит |
|---|---|
| [`network-api.md`](network-api.md) | Сетевой слой: приложение ↔ Go-сервис (JSON + SSE), хранилище студентов в PostgreSQL, механика логина и отметки в Moodle внутри сервиса |
| [`openapi.yaml`](openapi.yaml) | Формальное OpenAPI 3.0-описание API Go-сервиса (CRUD студентов, SSE-отметка, health) |
| [`app-flow.html`](app-flow.html) | Интерактивная диаграмма потока: сканер → сервис → параллельная отметка (Mermaid; открыть в браузере) |
| [`adr/0001-go-attendance-service.md`](adr/0001-go-attendance-service.md) | Архитектурное решение: перенос авторизации и отметки на Go-сервис с базой студентов, удаляемые механизмы, принятые риски |

## Быстрая навигация

- Хочу понять, почему приложение больше не ходит в LMS само → [`adr/0001-go-attendance-service.md`](adr/0001-go-attendance-service.md)
- Хочу понять, что делает приложение после сканирования QR → [`app-flow.html`](app-flow.html)
